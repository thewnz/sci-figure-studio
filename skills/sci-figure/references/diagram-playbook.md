# 流程图与概念图手册

## 先定拓扑，再定样式

| 内容结构 | 布局 | 阅读方向 |
| --- | --- | --- |
| 顺序 pipeline | `layered` | 左→右（横版）或上→下 |
| 分层架构 | `layered` | 上→下，层内并排 |
| 分支/汇合 | `layered` + 同 stage 多节点 | 左→右 |
| 反馈/迭代 | `layered` + dashed 回边 | 主线左→右，回边绕外侧 |
| 中心概念 | `radial` | 中心→四周 |
| 时间线 | `timeline` | 左→右 |
| 矩阵/特征筛选 | `matrix` | 网格 |
| 复刻参考图 | `freeform` | 归一化坐标 |

> 如果一张图需要读者来回跳转三次以上，优先拆成两个面板，而不是加更多箭头。

## 节点语义

- `process`：处理/模块；矩形。
- `decision`：判断；菱形，必须有至少两条带条件标签的出边。
- `io`：输入/输出/数据；平行四边形或文档形。
- `database`：存储；圆柱。
- `actor`：人/外部系统；圆形或人形。
- `terminal`：开始/结束；圆角矩形。
- `note`：注释；无边框或浅底。
- `group`：阶段/分区；只做背景框，不承载箭头。

节点文字规则：

- 一行只放一个概念；超过 2 行考虑拆节点。
- 用原文术语，不改写科学含义。
- 中文标签需要 CJK 字体；英文投稿优先英文标签。
- 公式用 Unicode 上下标或独立公式对象，不用图片。

## 箭头语义

| 关系 | 线型 | 箭头 | 标签 |
| --- | --- | --- | --- |
| 数据流 | 实线 | 单箭头 | 数据名 |
| 控制流 | 实线 | 单箭头 | 动作 |
| 反馈/迭代 | 虚线 | 单箭头 | 条件/次数 |
| 双向依赖 | 实线 | 双箭头 | 关系名（少用） |
| 可选/辅助 | 细虚线 | 单箭头 | `optional` |

- 箭头必须从源节点边缘出发、落在目标节点边缘；不要穿过无关节点。
- 条件分支的标签只写原文有依据的词；没有依据就留空，不要编“成功/失败”。
- 反馈边绕外侧走廊，避免破坏主阅读方向。


## 总览 + 局部放大

适用：方法框架、系统总览、graphical abstract、需要同时展示全局与关键步骤的图。

- 顶部 30% 左右放 2–4 个分组总览卡，组间用粗箭头连接。
- 底部 60% 左右放与分组一一对应的放大面板，面板用分组色虚线边界。
- 上下用梯形或虚线引导连接；面板角标 `a/b/c`。
- 每个放大面板 3–5 个图元，图元之间用短箭头表达局部流程。
- 总览卡只放迷你图元 + 分组名，不要塞满细节。
- 面板内部先放“输入→处理→输出”的主链，再放公式/表格等辅助信息。
- 标签短于 12 个字符；宁可直接标注，不要长图例。
- 组数 >4 或单栏宽度 <100 mm 时拆图，不要硬塞。

### rich / strict

- `rich`：彩色分组、半透明面板、色带渐变、3D 堆叠；适合预印本、汇报、图形摘要。
- `strict`：白底、细线、无渐变/阴影；正式投稿优先。
- rich 的渐变必须用多层色带模拟，不要用 SVG gradient/filter（MuPDF 转 PDF 会变黑）。
- rich 在 Nature/IEEE 等严格规范下审计会提示切 strict；不要把提示当错误，但投稿前要处理。

### 通用图元

| 图元 | 用途 | 注意 |
| --- | --- | --- |
| `spectrum_strip` | 光谱/波长/特征条带 | 色带分段；strict 用双色，rich 可用彩虹 |
| `tensor_stack` | 张量/特征图堆叠 | 用偏移+半透明模拟 3D，不用阴影滤镜 |
| `feature_matrix` | 特征矩阵/热图 | 单元格不宜过密 |
| `network` | 网络/注意力/节点关系 | 连线用虚线，节点同色 |
| `formula` | 公式/损失/指标 | 用 Unicode 下标，避免 baseline-shift |
| `bar_group` | 小柱状/排名/输出 | 不替代正式数据图 |
| `chips` | 输出编码/类别色块 | 颜色不是唯一编码 |
| `mini_table` | 元数据/验证表 | 只放 3–4 行 |
| `waveform` | 波形/信号/时序 | 不伪造真实数据，需标注示意 |
| `icon` | 芯片/数据库/显微等 | 线稿，统一线宽 |

## 视觉规则

- 白底；细线（0.5–1 pt）；少色（2–4 个语义色）。
- 阶段用左侧细色条/编号区分，不用大面积渐变或彩色卡片。
- 文字深灰/黑，不用彩色文字；颜色只标数据/阶段编码。
- 圆角 0–2 mm；不要阴影、发光、3D。
- 图标是辅助：线稿、统一线宽、单一颜色；不要用 emoji 或剪贴画。
- 留白优先：节点间距 ≥ 字号 × 1.5；画布边缘 ≥ 3 mm。
- 面板标签 `a/b/c` 或 `A/B/C` 按期刊规则，放在左上角。

## 概念图

- 一个中心命题 + 3–6 个支撑概念；超过 6 个改为分组。
- 图标只表达“是什么”，箭头表达“关系”；不要让图标承担精确数量。
- graphical abstract 只讲一个故事：问题 → 方法 → 结果/影响。
- 概念图的文字仍要能被检索和编辑；不要转曲。

## 可编辑交付

- SVG：节点是 `<g id="node-...">`，文字是 `<text>`/`<tspan>`，箭头是带 marker 的 `<path>`。
- Draw.io：节点/连线独立对象，便于手工微调。
- Mermaid：适合文本化版本管理，不适合最终排版。
- Illustrator：优先打开 SVG/PDF；改字后再导出 PDF。

## 常见错误

- 把“相关”画成“因果”。
- 用颜色区分阶段但灰度打印后全一样。
- 箭头穿过节点、交叉过多。
- 节点文字溢出边框。
- 图内出现正文没有的模块/指标。
- 用 AI 位图生成带术语的流程图，导致错字和不可编辑。
